# Сравнение линейной модели и Сен-Венана

## Запуск и результаты

Из корня проекта, Python 3.11:

```bash
python -m pip install -r analysis/requirements.txt
python -m analysis.compare
```

Сервер не требуется. Скрипт вызывает `MODELS[model_id].solve(Params(...))`
из `backend.registry`. Сетка, дно и начальная поверхность формируются моделями
через `backend/common.py`. Код моделей, контракт и фронтенд не изменяются.

| Файл | Содержимое |
|---|---|
| `figures/compare_flat_map.png` | карта расхождения «амплитуда × время», порог 10% и теоретическая кривая t*(a) |
| `figures/compare_t10.png` | t₁₀ от амплитуды в двойном логарифмическом масштабе, зависимость 1/a и найденный наклон |
| `figures/compare_gulf_boundary.png` | профиль залива с местом первого достижения порога для каждой амплитуды |
| `results/compare_flat.npz`, `results/compare_gulf.npz` | координаты, времена, амплитуды, d(t), локальные моменты превышения и максимумы расхождения |
| `results/compare_summary.json` | параметры опытов, таблицы t₁₀, координат и глубин, проверка сетки и ограничения |

Пути в таблице указаны относительно `analysis/`.
Поле `params` в JSON задаёт шаблон опыта: a переопределяется для каждого
элемента `amplitudes` в NPZ и каждой строки `records` в JSON. Для `gulf`
параметр L игнорируется общим модулем; фактическая длина сохранена отдельно
в `actual_domain_length_m`.

## Метрика и определение границы

Для каждого сохранённого момента времени вычисляется строго заданная метрика:

\[
d(t)=\frac{\max_x|\eta_{\rm СВ}(x,t)-\eta_{\rm лин}(x,t)|}{a}.
\]

Знаменатель a — входной параметр `Params.a`. У пакета на переменном дне
максимум поверхности может быть немного меньше a из-за гладкой огибающей.
Нормировка не меняется на измеренный максимум. Отношение максимума начальной
поверхности к a сохранено в JSON.

t₁₀ — **первый сохранённый момент с d > 0,1**. Равенство 0,1 не считается
превышением. В JSON также записан предшествующий момент: физическое пересечение
находится между этими кадрами, если до него не было пропущенного короткого
превышения. Пропущенный порог записывается как `null`, а не как конец расчёта.

Для залива «граница» на третьем рисунке определяется так: в первом кадре
с глобальным d > 0,1 берётся координата максимальной разницы профилей.
Записываются время, координата вдоль разреза, глубина и расстояние от берега
`x[-1] - x`. Это место первого наблюдаемого расхождения в данном опыте,
а не неподвижная граница и не зона по условию a/h > 0,1.
Для каждой точки разреза дополнительно сохранено первое локальное превышение.

В линейной модели берег отражает волну у последнего мокрого узла, в Сен-Венане
возможен накат. Поэтому граница принимается только до первого кадра, когда
в любой из моделей |η|/a у последнего изначально мокрого узла превысило 0,001.
После этого пространственный результат получает отдельный статус, а не
выдаётся за границу чистого распространения. В текущих опытах береговая
реакция за выбранное время не зарегистрирована.

## Постановка опытов

Это вычислительные опыты по `TASKS.md`, не реконструкция исторического наводнения.

**Ровное дно:** 10 амплитуд от 0,05 до 1,5 м с равномерным шагом по логарифму.
Глубина 5 м, длина волны 100 м, периодическая область 1000 м, 3200 узлов,
время 160 с, шаг кадров 0,1 с. В области ровно десять периодов синусоиды.
Время выбрано так, чтобы показать и t₁₀, и теоретическое время опрокидывания
даже для минимальной амплитуды.

Теоретическая кривая для синусоиды:

\[
t_*(a)=\frac{\lambda}{3\pi(a/h)\sqrt{gh}}.
\]

t* — время укручения, оно не приравнивается к t₁₀. При a/h до 0,3 формула
остаётся слабонелинейной оценкой. Для выбранных параметров kh ≈ 0,314:
это пограничное мелководное приближение из базовой постановки проекта,
немного выше ориентира 0,3. Сравниваются именно заданные уравнения мелкой воды;
точность относительно полной теории волн этим опытом не устанавливается.

**Залив:** 10 амплитуд 0,2; 0,4; …; 2 м. Дно — `data/gulf_profile.npz`,
3201 расчётный узел. Длина волны 10 км, пакет из трёх периодов длиной 30 км
с общей огибающей, время 7000 с, шаг кадров 10 с. Пакет помещается в область
длиной 181,42 км; kh по максимальной глубине около 0,0365.
Длина волны выбрана как разрешимый длинноволновый опыт, не как измеренное
значение. Значения по умолчанию для лабораторной области здесь не используются:
при λ=100 м и 400 узлах на этом профиле начальный пакет пропускается сеткой.

Начальная поверхность и геометрия в двух моделях совпадают. Начальные
скорости берутся из штатных функций общего модуля: `u_linear` и `u_simple_wave`.
Они отличаются на нелинейную поправку. Поэтому это сравнение двух штатных
постановок правобегущей волны, а не опыт с абсолютно одинаковым начальным
вектором (η, u). Формулы не подменяются в скрипте анализа.

## Численная проверка

Для минимальной и максимальной амплитуды каждого опыта число пространственных
узлов увеличивается примерно вдвое, а интервал кадров уменьшается вдвое.
Уточнённый расчёт выполняется до момента после найденного первого превышения;
он проверяет начало расхождения, а не всю позднюю эволюцию.

Также обе модели запускаются при a=0,0001 м на исходной сетке и всём временном
интервале. Для этой пары моделей предел малых амплитуд должен совпадать;
оставшееся расхождение оценивает преимущественно различие численных схем.
Оно не вычитается из метрики d и не является строгой верхней границей ошибки.

| Опыт | Максимальный d в малом контроле | Изменение t₁₀ при уточнении крайних амплитуд |
|---|---|---|
| Ровное дно | 0,00748, около 0,75% | 0,18% и 0% |
| Залив | 0,01953, около 1,95% | 0% и 2% |

Для залива положение границы на крайних амплитудах изменилось на 0 и примерно
142 м. Дискретность времени первого превышения — 10 с на основной сетке.
Эти оценки относятся к проведённым проверкам, а не ко всем возможным параметрам.
Порог предупреждения для малого контроля в скрипте — 3%, для изменения
t₁₀ — 5%; это внутренние диагностические ориентиры, не требования TASKS.md.

## Полученный результат

На ровном дне наклон аппроксимации log(t₁₀) от log(a) равен **−1,007**,
что согласуется с ожидаемой зависимостью 1/a. При a=0,05 м t₁₀=28,4 с,
при a=1,5 м — 0,9 с. t₁₀ находится раньше теоретического опрокидывания.

|---|---|---|---|
| 0,2 | 1500 | 133,91 | 24,84 |
| 0,4 | 1030 | 142,25 | 36,01 |
| 0,6 | 810 | 146,67 | 47,05 |
| 0,8 | 620 | 152,96 | 54,30 |
| 1,0 | 500 | 155,74 | 56,41 |
| 1,2 | 420 | 157,61 | 57,67 |
| 1,4 | 360 | 159,03 | 56,57 |
| 1,6 | 310 | 160,22 | 55,27 |
| 1,8 | 280 | 160,90 | 54,56 |
| 2,0 | 250 | 161,58 | 53,86 |

Для выбранного пакета расхождение возникает ещё в открытой части залива,
а при больших амплитудах — внутри области начального пакета. Это накопленное
искажение профиля; локальный критерий a/h даёт другой ответ и не заменяет d.
Переносить эти расстояния на другую длину волны или исторический нагон нельзя.

## Связь с последующими сравнениями

`solve_pair` принимает идентификаторы зарегистрированных одномерных моделей
и `Params`, проверяет согласованность сеток и возвращает поле расхождения.
Его можно использовать для сравнения с КдФ и Буссинеском. Ограничения моделей
сохраняются: например, КдФ поддерживает только ровное дно. Интерфейс для 2D
не подменяется одномерными метриками. Контроль малой амплитуды при добавлении
дисперсионных моделей может включать физическую дисперсию, поэтому его нельзя
автоматически считать только численной ошибкой.

NPZ содержит `amplitudes`, `x`, `t`, `h`, `d[амплитуда, кадр]`,
`first_local_crossing_s[амплитуда, узел]`, `peak_local_difference_before_coast`,
`small_amplitude_d`, `threshold`, `reference`, `model`, `t_star`.
Локальные времена и максимумы в `gulf` исключают кадры после береговой реакции;
глобальный d сохранён на всём интервале. В `flat` берегового ограничения нет.
NaN в локальном времени означает отсутствие превышения. В JSON этому
соответствуют `null` и явный статус. Файлы читаются без pickle.
