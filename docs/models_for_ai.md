# Модели проекта «Волны Финского залива» — справка для ИИ-агента

Назначение: дать агенту, который будет менять или проверять код, точную картину того, что и как считается.
Формулы в Unicode/LaTeX-нотации, единицы СИ, g = 9.81. Ветка с полным набором: `vanya/showcase-3d`.

## 0. Общая рамка

- **Контракт** `backend/contract.py`. `Params`: `a, wavelength, depth, bottom ∈ {flat, slope, gulf}, depth_shore, L, t_end, nx, n_frames, extra: dict`. `Result`: `x, t, eta, h, y?`. Для `dim=1`: `eta[кадр][ix]`, `h[ix]`; для `dim=2`: `eta[кадр][iy][ix]`, `h[iy][ix]`, плюс `y`. `WaveModel.extras(p)` сливает `extra_params` по умолчанию с `p.extra`.
- **Общая постановка** `backend/common.py → setup(p)`. Все 1D-модели берут сетку, дно и η₀ отсюда, иначе их нельзя сравнивать.
  - `flat`: `x = j·L/nx` (периодическая, узел nx совпал бы с 0), `h = depth`, `η₀ = a·sin(kx)`, периодика.
  - `slope`: `linspace(0, L, nx)`, h линейно от `depth` до `depth_shore` (≤ 0 → сухой берег), стенки.
  - `gulf`: профиль `data/gulf_profile.npz` (181,4 км, 801 точка, h = 0 в последнем узле), интерполяция на `nx`, стенки.
  - Для slope/gulf η₀ — пакет из `N_PACKET = 3` периодов с огибающей sin²(πs/3λ) у левого края, η₀ = 0 на суше.
  - Начальная скорость зависит от модели: `u_linear = η·√(g/h)` (линейная), `u_simple_wave = 2(√(gH) − √(gh))` (нелинейные; инвариант Римана u − 2√(gH) как у покоя, волна строго вправо).
- **Регистрация** `backend/registry.py`, API `backend/main.py` (`GET /models`, `POST /simulate`). Каждая модель запускает свои проверки командой `python -m backend.models.<id>`.
- **Безразмерные числа**: ε = a/h (нелинейность), μ = (h/λ)² (дисперсия), Ur = aλ²/h³. Время градиентной катастрофы синусоиды t* = λ/(3π·ε·c₀), c₀ = √(gh). Для умолчаний (a = 0,5, λ = 100, h = 5) t* ≈ 15,1 с.

## 1. `linear` — линейная мелкая вода (база сравнения)

- Уравнения: η_t + (h u)_x = 0, u_t + g η_x = 0.
- Сетка разнесённая: η в узлах, u на гранях и сдвинута на Δt/2 (схема «крест», 2-й порядок по x и t). CFL = 0.99 по c_max = √(g·max h).
- Стенки: поток через стенку 0, крайняя ячейка вдвое короче (множитель 2 в дивергенции). Периодика через `np.roll`.
- Кадры между шагами — квадратичная интерполяция по времени. t_end попадает ровно на целый шаг.
- Проверки: полный оборот на ровном дне — ошибка 0,16 % от a; закон Грина h^(−1/4) на склоне — отклонение 3,9 % (допуск 10 %).

## 2. `saint_venant` — нелинейная мелкая вода 1D (автор — Ваня)

- Переменные (H, q = H u), z = −h. Уравнения: H_t + q_x = 0, q_t + (q²/H + gH²/2)_x = −gH z_x.
- **Конечные объёмы**, ячейки = узлы `setup`. По две фиктивные ячейки на краю: `wrap` для периодики, зеркало (`symmetric`, u с минусом) для стенок.
- **Реконструкция** MUSCL κ = 1/3 с ограничителем Корена по H, w = H + z и u отдельно:
  inc_E = ½·minmod(2Δ₋, (Δ₋ + 2Δ₊)/3, 2Δ₊), inc_W = −½·minmod(2Δ₊, (2Δ₋ + Δ₊)/3, 2Δ₋).
  `minmod(a,b,c) = max(min(a,b,c),0) + min(max(a,b,c),0)`. Если хоть одна ячейка шаблона сухая (H < H_DRY), реконструкции нет.
  Почему не κ = 0: при 100 ячейках на длину волны схема 2-го порядка теряла ~1 % амплитуды за 10 длин волн и не проходила закон Грина.
- **Гидростатическая реконструкция** (Audusse et al. 2004): z* = max(z_E, z_W), H*_{L,R} = max(0, w_{L,R} − z*). Поток HLL по (H*, H* u). Поправки к потоку импульса: F⁻ = F + g/2·(H_L² − H*_L²), F⁺ = F + g/2·(H_R² − H*_R²), центральный источник −g/2·(H_E + H_W)(z_E − z_W). В итоге покой над любым дном точен до 10⁻¹⁵.
- **HLL**: s_L = min(u_L − c_L, u_R − c_R, 0), s_R = max(u_L + c_L, u_R + c_R, 0). Если s_R − s_L = 0 (две сухие ячейки), поток 0.
- **Скорость без деления на ноль** (Kurganov–Petrova): u = 2Hq/(H² + max(H², H_EPS²)), H_EPS = 1e−3 м; при H ≤ H_DRY = 1e−6 м u = 0. После каждой стадии H = max(H, 0), q = H·u.
- **Время**: SSP-RK2 (Хойн), CFL = 0.5 по max(|u| + √(gH)). Шаг укорачивается, чтобы попасть точно в момент кадра.
- Сухой берег и накат работают (depth_shore ≤ 0).
- Проверки: путь за оборот −0,01 %, амплитуда −0,6 % (a = 0,01); масса — машинная точность; вертикальный фронт 15,2 с при t* = 15,1 с (по экстраполяции 1/max|η_x| к нулю по участку, где наклон < 3·начального); покой над склоном с сушей 2·10⁻¹⁵ м; Грин 4,5 % (a = 1 мм, nx = 4000: при a = 1 см волна укручается у берега); накат 713 → 759 → 712 м.
- Общие функции `_faces`, `_koren`, `_minmod`, `_hll`, `_velocity` работают вдоль последней оси массива любой размерности; их переиспользует `shallow_2d`.

## 3. `kdv` — Кортевег — де Фриз (автор — Саша)

- η_t + c₀η_x + αηη_x + βη_xxx = 0, α = 3c₀/(2h), β = c₀h²/6. Волна только вправо, только ровное дно (выведено для h = const), область периодическая.
- Псевдоспектральная схема: производные через `rfft`; по времени ETDRK4 (Cox–Matthews; Kassam–Trefethen). Коэффициенты φ-функций — среднее по контуру из 32 точек вокруг z, чтобы не терять точность при малых |z|.
- Линейная часть (c₀k, βk³) интегрируется точно, шаг ограничен только нелинейностью: α·max|η|·k_max·Δt = 0.1. Нелинейный член `−(iαk/2)·(η²)^` с подавлением наложения по правилу 2/3.
- Проверки: солитон A·sech²((x − Vt)/Δ) проходит область с ошибкой формы < 0,01 %; ∫η и ∫η² сохраняются до 10⁻⁶; горб 0,5 м шириной 2 км на 20 м (Ur ≈ 250) распадается на цепочку солитонов. При Ur ≈ 16 теория даёт один солитон, задание поправлено.

## 4. `boussinesq` — Перегрин (автор — Анушервон)

- η_t + [(h + η)u]_x = 0; u_t + u u_x + g η_x = (h/2)(h u_t)_xx − (h²/6) u_xxt. Дисперсия ω² = ghk²/(1 + (kh)²/3); на kh ≤ 2 совпадает с формулой до 0,06 %.
- Сетка узловая, центральные разности 4-го порядка. Неявно по w = u_t: w − (h/2)(h w)_xx + (h²/6) w_xx = RHS — трёхдиагональная система (`solve_banded`). Для периодики система циклическая, угловые элементы снимаются поправкой Шермана — Моррисона.
- Время: RK4, CFL = 0.5. После шага фильтр Шапиро, σ = 0.05 (гасит пилу с шагом в узел).
- **Обрушение** (Kennedy et al. 2000): если размах η в окне длиной λ (`maximum_filter1d − minimum_filter1d`) превышает γ·h, γ = 0.78, включается вязкость ν = B·δ²·h·max(η_t, 0), δ = 1.2; B растёт от 0 до 1 при H/h от γ до 1,2γ. При вязкости шаг дополнительно ограничен: dt ≤ 0.25·dx²/ν_max.
- **Наката нет**: берег — стенка в первом узле, где h < max(a, H_WALL = 0.25 м); дальше η = 0. Если H ≤ 0, расчёт бросает `RuntimeError` («волна осушила дно»).

## 5. `shallow_2d` — двумерная мелкая вода на карте залива (автор — Ваня)

- Карта `data/gulf_bathymetry.npz`: x (150), y (50) — центры ячеек в метрах (локальная цилиндрическая проекция, опорная широта 60°), h[iy, ix], суша h = 0; ячейка ≈ 1,26 × 2,67 км. Ещё lon, lat.
- Уравнения (theory 2.5): η_t + ∇·(H**u**) = 0; **u**_t + (**u**·∇)**u** + f **e**_z × **u** + g∇η = **τ**/(ρH) − ∇p_a/ρ − C_f|**u**|**u**/H.
  - f = 1.26e−4 (выключается `coriolis = 0`).
  - **τ** = ρ_a·C_d·|**W**|**W**, ρ_a = 1.25, C_d = 2e−3, ρ = 1000. `wind_dir` — откуда дует (270 = западный); вектор W направлен «куда». Ветер действует только при H > 0.1 м.
  - Давление: перепад `dp` гПа запад − восток, равномерный градиент по ширине карты.
  - Трение C_f — полунеявно после каждой стадии: (Hu, Hv) /= 1 + dt·C_f·|u|/H.
- **Схема** та же, что в `saint_venant` (Корен, гидростатическая реконструкция, HLL, SSP-RK2), но потоки считаются по **списку граней** (`_mesh`/`_fluxes`). Взяты только грани, у которых хотя бы с одной стороны вода, x- и y-грани вместе; для каждой грани хранятся индексы LL, L, R, RR вдоль нормали; выборка — `np.take` по заранее посчитанным плоским индексам, для y-граней u и v переставлены. Касательный расход переносится по знаку массового потока.
  - Суша и края карты — стенки: массовый и касательный потоки 0, нормальный импульс = g/2·H² со стороны воды (это и есть гидростатическая поправка, поэтому покой у берега точен).
  - CFL = 0.8 для суммы (|u|+c)/dx + (|v|+c)/dy.
- **Западная открытая граница** (только `gulf`): две фиктивные ячейки на мокрых строках колонки 0. Входящий инвариант R⁺ = u_in + 2√(g(h + η_in)), u_in = 2(√(g(h+η_in)) − √(gh)); исходящий R⁻ = u − 2√(gH) из граничной ячейки; c = (R⁺ − R⁻)/4, H = c²/g, u = (R⁺ + R⁻)/2. Входной сигнал — один горб η_in = a·sin²(πt/T) при t ≤ T, T = wavelength/√(g·h̄_запад). Отражённая волна уходит свободно.
- **Режимы дна**: `gulf` (по умолчанию), а `flat`/`slope` — проверочный канал: 1D-постановка `saint_venant`, вытянутая на ny = 4 ряда, стенки по y.
- **Выход**: до 60 кадров (лимит для браузера), η округлена до 0,1 мм. `solve_2d(..., return_uv=True)` дополнительно возвращает кадры u, v (для визуализации течений).
- Проверки: канал против `saint_venant` 2,4·10⁻³·a (разный шаг по времени); ветровой перекос 20 км × 5 м при 25 м/с — 0,634 м против 0,637 м по τL/(ρgH); покой на карте 2·10⁻¹⁴ м; волна 0,3 м × 300 км у Петербурга ×2,9 (Грин без сужения 1,7); зона a/h > 0,2 (0,3) на 86 % (96 %) в Невской губе (восточнее 29,6° в. д.); 0,5 м + 25 м/с → +3,20 м у Горного института; 150 × 50 на 12 ч — 5–7 с.
- Подвох: при ветре 25 м/с зона a/h > 0,2 выходит и на другие мелководья (Лужская губа, Выборгский залив) — «нелинейность только в губе» верно для умеренных волн.

## 6. Разрез по клику — `showcase/section.py` (сервер `/section`)

- **Путь** — наименьшее время пробега (принцип Ферма): Дейкстра по мокрым ячейкам карты 150 × 50, 8 соседей, вес ds·½(1/√(gh₁) + 1/√(gh₂)), источник — все мокрые ячейки колонки 0. Клик на суше привязывается к ближайшей воде в радиусе 3 ячеек.
- Путь продолжается от точки по направлению последнего участка шагами 200 м до берега (h ≤ 0.2), сглаживается по Чайкину (3 раза), пересэмплируется на NX = 1000 узлов. h(s) — билинейно по карте; внутри пути h ≥ H_MIN = 1 м, последний узел h = 0.
- Пакет как в `common` для gulf (3 периода, sin²). t_end: пока пакет пройдёт точку щелчка, но до прихода отражения от берега.
- Модели: `solve_linear` (u_linear), `solve_sv` (u_simple_wave), `solve_boussinesq` (стенка при h < max(H_WALL, a); при `RuntimeError` стенка переносится на 2a, затем на 4a; если не помогло — Буссинеск на пути не считается). Сен-Венан и Буссинеск идут параллельно в `ProcessPoolExecutor(2)`.
- «Фронт ×2»: наибольший |η_x| за время в узле у Сен-Венана, делённый на линейный; сравнение только там, где линейный наклон ≥ 0.05·a·k. Ответ: 400 узлов × 160 кадров + сводка в точке.
- Совпадает с таблицей 3.3 `docs/report.md`: у губы линейная 0,90 м, Сен-Венан 0,21, Буссинеск 0,26.

## 8. Затопление улиц — GPU, `showcase/static/city.js` (+ `flood_map.py`)

- **Модель виртуальных труб** (Mei et al. 2007), упрощённая мелкая вода. Состояние — RGBA32F-текстура: R = глубина d, GB = скорость (для пены). Расходы — вторая текстура: RGBA = в лево/право/низ/верх. Две ping-pong пары.
  - Расходы: f ← max(0, 0.998·f + dt·g·cell·Δh) по каждому соседу, Δh = (b + d)_self − (b + d)_nbr. К стене расход 0. Затем масштаб K = min(1, d·cell²/(Σf·dt)), чтобы не вытечь больше, чем есть.
  - Глубина: d ← max(0, d + dt·(Σf_in − Σf_out)/cell²).
  - Морские ячейки на краю зоны (флаг в B-канале рельефа): d = max(0, η_море − b), Дирихле. η_море — из текущего 2D-сценария в ячейке у зоны или задаётся вручную.
  - dt = min(0.5, 0.25·res/√(g·10)). Обновление не чаще 30 раз в секунду, по 6 подшагов.
- **Карта рельефа** `flood_map.py`: сетка не больше 512 по стороне (Васильевский 512 × 384 по 10,3 м, Кронштадт 512 × 305 по 10,9 м).
  - Земля — тайлы Terrarium z14, но в городе это поверхность вместе с крышами (DSM SRTM). Земля оценена так: минимум по окну 250 м, гаусс 60 м, не ниже 1 м. Точность ±2–3 м — это главное ограничение для вывода «затопит ли».
  - Вода — по контурам OSM (`natural=water`, `riverbank`, `coastline`) как границам: связные области с медианой DSM < 4 м и без дорог. Дно рек и залива в зоне −4 м.
  - Здания (контуры OSM без висящих частей) — код 32000, стена. Набережные (`man_made=quay` и др.) — +1 м парапета.
  - Канал G текстуры рельефа — земля под зданием (для отрисовки воды у стены), A — признак воды.
- Вода затопления рисуется только над сушей (A = 0); море и реки зоны рисует общая вода залива.

## 9. Только визуализация (не физика модели)

- Рябь на воде залива: 11 октав от 6 км до 18 м, ω = √(gk) (глубокая вода), видны только октавы, которые экран разрешает (L/mpp > 3…9).
- Свободная камера (`dive.js`): кольцевая сетка вокруг камеры (112 тыс. вершин); 8 волн Герстнера по ветру сценария. Частоты — ω² = gk·tanh(k·h_камеры): глубина берётся под камерой, а не поточечно, иначе фаза разъезжается. Шоалинг по амплитуде (Экарт, K_s = √(c_g0/c_g)), обрушение при H > 0,78h (амплитуда срезается до 0,39h), пена по якобиану Герстнера, у берега (SDF) и у стен (по текстуре рельефа города).
- Дно в свободной камере: EMODnet (сетка залива ~115 × 230 м; Невская губа бикубически до 25 м + знаковое расстояние до берега). Морского канала в EMODnet нет. Под водой — окно Снеллиуса (cos 48,6° ≈ 0,661), туман, каустики.
- Фасады: этажи и окна по метрам стены, interior mapping (луч в коробке 3,2 × этаж × 4 м), отражение неба по Френелю. Ближе 600 м — окна и бордюры, до 6 км — блоки, дальше кварталы скрыты.

- Отрисовка в Web Mercator. Каждая зона города рендерится относительно своего угла (RTC): матрица «камера × угол зоны» считается в JS в double, иначе float32 в 180 км от центра залива даёт дрожание в метры.
- UV снимка города — формула тайлов Slippy Map от lon/lat вершины; склейка тайлов без пересэмплирования, границы — по индексам крайних тайлов. Контроль совпадения — 0 пикселей.
- Загрузчик three.js переворачивает картинку (`flipY`), UV склейки отсчитываются от севера: в шейдере `1 − v`. Это и было причиной прежнего зеркального сдвига.

## 11. Подводные камни, на которых уже обожглись

- 3D-рельеф MapLibre + `panBy`/перетаскивание → синхронный `readPixels` на каждом сдвиге (67 % времени главного потока). Поэтому рельеф только при z < 11, полёт WASD — `jumpTo` по расчёту.
- Разрешение: на 2880 × 1660 при плотности 2 видеокарта красит 4,8 млн пикселей. В городе внутреннее разрешение 1×, вне — ≤ 1,5×; менять его только на входе/выходе (каждая смена пересоздаёт буферы карты).
- Главный цикл обёрнут в try/catch: одно исключение кадра раньше «замораживало» картинку.
- `boussinesq` падает на мелком пути (осушение) — в разрезе есть откат стенки на 2a/4a.
- `common.py` и `contract.py` меняет только Саша; чужие файлы в общих каталогах не правим.
